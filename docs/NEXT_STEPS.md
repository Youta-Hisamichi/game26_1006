## 2. 元コードで見つけて直した不具合

| # | 症状 | 原因・対処 |
|---|---|---|
| 1 | 手札から外したカードが別のカードとして復活する | `selectCard6` が自分の配列ではなく**敵の** `_card5_to12_i` を参照していた |
| 2 | 同じカードを両者が持つとHPが共有される | 自分と敵のデッキが同じオブジェクトを参照。ユニットごとにインスタンス化 |
| 3 | 敵のセンスが「ヒット」で無効化されたとき、**攻撃自体が消える** | 敵側の処理だけ `return` していた。さらに、ヒットで無効化すると「命中+3」まで失われていた（無効化＋命中+3の両方が効くように修正） |
| 4 | 敵のヒールが常に先頭ユニットしか回復しない | `TODO` のまま。ヒール対象を**スロット指定**にし、AIは傷ついたユニットを選ぶ |
| 5 | 自分のヒール対象が「名前検索」で、移動や同名で別ユニットになりうる | 同上（スロット指定に変更） |
| 6 | 敵がしえんを使うと「自分の」使用済みフラグが立つ | `_my_o._isEndSien = true` の書き間違い |
| 7 | 行動順がコメントの仕様と逆になる場合がある（敵のいどう vs 自分のしえん） | 「ガード→いどう→しえん→こうげき」を優先度として実装し、同順位だけAGI（同値は2D6）で決定 |
| 8 | こうげきの条件（1R=AGI6以上、2R=AGI4以上）が「元の先頭カード」で判定され、いどう後の並びを無視 | 計画中の想定配置で判定 |
| 9 | 全滅しても試合が続く | 前列が全滅した時点で決着 |
| 10 | 変数 `i` の暗黙グローバルでループが干渉しうる | モジュール化・`let` 宣言 |
| 11 | SPの払い戻し処理が各所に散在 | 計画中はプレビュー、バトル開始時に確定消費の一本化 |
| 12 | `viewport=1020` 固定でスマホ不可、`<html>`が二重、`</html>`の後にスクリプト | 作り直し |
| 13 | 相手の計画が丸見え、「ラウンドごとの結果」がログの山に埋もれる | 相手の行動はそのラウンドで初めて公開。ログは「次へ／オート／スキップ」で再生 |

## 3. 「カード上の機能が欠けている」の中身

カード画像（`assets/card/unit_*.png`）には、ゲームに**まだ入っていない効果**が大量に書かれています。現状のモックは、全カード共通で次のダミーを使っているだけです。

- こうげき2 = 「防御+2」／こうげき3 = 「ATK+2」（カードごとの技2・技3の中身は未反映）
- 特性（パッシブ）は**全く未実装**
- 属性（けん／ま／ゆみ／ふし／りゅう）は表示されるだけで効果なし

画像から全47枚の技・特性を転記しました（**赤丸のAP値はデータと自動照合済み**。効果の文言は目視転記なので実装前に実物と照合してください）。

- 一覧：[`docs/CARD_TEXT.md`](CARD_TEXT.md)
- 構造化データ：[`docs/card_skills.json`](card_skills.json)

## 4. 次にすべき作業（優先順）

### P1　技をデータ駆動にする（まずここ）
1. `docs/card_skills.json` を `js/data.js` に取り込み、カードごとに技2・技3（AP/SP/効果）を持たせる
2. 効果を**小さな部品**として定義し、エンジンで解釈する
   - 加算系：`ATK±n / DEF±n / AGI±n / 命中±n / CT値±n / ダメージ-n`（数が多く、最初に効く）
   - 代入系：`ATK=AGI`、`ATK=5` など
   - 条件：`偶数ラウンド`、`命中n以上`、`HPがn以下`、`相手のコストがn以下`
   - 攻撃の形：`2回／3回攻撃`、`攻撃後n点ダメージ`、`前列全体へn点`
3. 現在のダミー（lv2=防御+2、lv3=ATK+2）を、`engine.js` の `attack()` 内の分岐から「技データの効果リスト」を適用する処理に置き換える
4. 行動選択シートに「技の名前・効果文」を表示する（`ui.js` の `openActionSheet`）

### P2　特性（パッシブ）のためのイベントフック
`onMove / onDamaged / onEvade / onDeath / onRoundEnd / onAttackHit` のような**フック**をエンジンに用意し、特性はフックに登録する形にする。最初は「SPマーカーを得る」系（ファイター、ソーサラー、ハンター等）が手頃。

### P3　みはり台
置き場（人数上限）・置く／破棄／奪う操作・しえんとの関係を決めてから、`engine.js` に状態を追加。13枚に関わるので、P1の次に優先度が高い。

### P4　装備・補給フェイズ・発掘
画像は揃っているので、**アイテムカード文言の転記** → 装備スロットの設計 → 補給フェイズの追加、の順。

### P5　遊びやすさ
- 対話式チュートリアル（現在は「あそびかた」のテキストのみ）
- 効果音／BGM、ターン開始やクリティカルの演出強化
- 進行状況の保存（途中再開）、戦績
- デッキ構築（現在は preset とランダム12枚から編成）
- 2人対戦（ホットシート／オンライン）

### P6　テスト
`tests/sim.js` は「不変条件が壊れない」ことだけを見ています。効果を足すたびに、**効果ごとの単体テスト**（固定乱数 `R5.makeRng(seed)` で再現）を追加してください。

## 5. 設計者に確認したいこと

実装前にルールの意味を確定させたい点です（カード文言から意味を推測できないもの）。

1. **「確定状態」** … 「確定状態の敵すべてに1ダメージ」の「確定状態」とは？（ブレス等で使用）
2. **「反転効果」** … 特性の「（反転効果）」は、どんなときに発動する効果の裏返し？
3. **「間接ダメージ」** … 通常こうげき以外の技ダメージ（攻撃後n点ダメージなど）のことか
4. **こうげき1／2／3** … 技2・技3は「こうげき＋効果」と理解してよいか（「DEF+2」「ダメージ-2」「HP回復」のみの技もあるため）
5. **「AP上限」** … APは「上限」で、技はAP以下のものが使える、という理解でよいか（モックはこの前提）
6. **「SPマーカーを得る」／「未設置のSPマーカー」** … モックの「SP」と同じものか。「設置」とは何に置くことか
7. **勝敗** … 現在は「生き残ったユニットのコスト合計」。宝（treasure）の要素は勝敗に関わるか
8. **しえんの消費** … 使ったしえんカードは捨て札でよいか（現在：使った時だけ消費。使わなければ控えに戻る）

## 6. 既知の仕様判断

- `AP` が足りなくても「こうげき1」は常に可能（元モックの挙動）。カードの赤丸APを厳密に使う場合は、設定で「カードのAPコストを厳密に適用」をON
- クリティカルは「2D6が12以上（クイック中11以上）」でDEFを無視。ヒット補正やクイックの命中+1はクリティカル判定に加算しない
- ヒットで相手のセンスを無効化したときも、ヒットの命中+3は有効
- ブレイク・パリィは「命中した時」に消費、ヒットは「こうげきした時」に消費、センスは「こうげきを受けた時」に消費
